# Project-4: Debouncing a Switch

## Project Overview

In Project 3, we observed that switch inputs did not always toggle properly. This issue occurs due to physical switch bounce: when mechanical contacts inside a switch or push button close or open, they bounce rapidly before settling into a stable electrical state. Reading inputs during this transition phase causes timing violations and unwanted pulse edges (glitches).

This project implements digital debouncing logic to filter out mechanical bouncing and deliver clean single-pulse transitions to the FPGA logic.

**Project Structure**:

```txt
project_4.srcs
|---- sources_1/new/top.sv 
|---- sources_1/ip/clk_wiz_0/clk_wiz_0.xci
|---- sources_1/new/LED_Toggle.sv
|---- sources_1/new/Debounce_Filter.sv
|---- constrs_1/new/io_pins.xdc
```

### Design Decisions

- Normally, a human push-button press lasts between *100 ms and several seconds*. Fast, deliberate presses typically complete in *50 ms to 100 ms* (based on stack overflow, and electrical engineers stack exchanange).
- A *10 ms* delay threshold is **standard** for filtering out mechanical contact bounce for most tactile switches. However, noisier switches often use *20 ms* or *50 ms* thresholds for added noise immunity.
- To compare behavior under different timing constraints, this design debounces two independent input switches to toggle two separate output LEDs:
  - Switch 1: Debounced using a 10 ms delay threshold.
  - Switch 2: Debounced using a 20 ms delay threshold.
- Use a `10 MHz` system clock generated via the Vivado Clocking Wizard IP.
- Two Debounced i/p signals used to control onboard LEDs.
